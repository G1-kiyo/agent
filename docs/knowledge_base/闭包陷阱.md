# React 闭包陷阱（Stale Closure）案例与知识点总结

## 一、核心案例

### 案例 1：事件订阅拿到旧 state
在组件 B 中定义函数 a，函数 a 内部使用组件 B 的 state，
通过 `addEventListener` 订阅事件并绑定函数 a。
触发事件后，函数 a 拿到的是初始 state，而不是最新 state。

### 案例 2：state 作为参数传给函数 a
把 state 作为参数传给函数 a：
- **订阅时传参** → 依然拿到旧值
- **触发时动态传参** → 才能拿到最新值

### 案例 3：回调涉及多个 state
滚动事件回调中调用了封装好的接口请求函数，
该函数内部使用了多个外部 state。
结果：所有 state 都拿到旧值，闭包陷阱具有"传染性"。

### 案例 4：改用 onScroll + useCallback 后正常
不用 `addEventListener`，改用 JSX 的 `onScroll` 并配合 `useCallback`
包裹请求函数，问题消失。

### 案例 5：addEventListener 加依赖 + useCallback 后连续触发 N 次请求
在 `addEventListener` 的 `useEffect` 中加上依赖并重新绑定，
同时用 `useCallback` 包裹请求函数，
结果一滑到底部就触发 N 次连续请求。

### 案例 6：组件卸载时 removeEventListener 解决连续触发
在 `useEffect` 的 return 中调用 `removeEventListener`，
连续触发问题消失。

## 二、知识点总结

### 1. 闭包陷阱的本质
- React 函数组件每次渲染都会创建**全新的 state 变量**和**全新的函数**。
- 闭包保留的是**引用**，但引用的是"旧渲染时的变量地址"，而不是"最新值"。
- 问题根源不是闭包本身，而是**订阅的是旧函数，旧函数引用了旧 state 变量**。

### 2. 为什么每次渲染 state 是新变量
- React 状态是不可变的（Immutable），`setState` 不会修改旧变量，而是创建新变量。
- 这是 React 精确判断哪些组件需要重新渲染的基础。

### 3. 三种标准解决方案

| 方案 | 做法 | 适用场景 |
|------|------|----------|
| **useRef** | 用 ref 保存最新值，事件回调读 ref | 改动最小，推荐 |
| **useCallback + 重新订阅** | 依赖 state，每次变化重新绑定 | 逻辑清晰，但频繁触发时性能差 |
| **函数式更新** | `setState(prev => ...)` | 必须基于旧值计算时 |
| **useMemoizedFn（ahooks）** | 引用不变，内部永远最新 | 最推荐，第三方库可用时 |

### 4. 多个 state 的处理
- 用 `useCallback`：所有用到的 state 都要放依赖数组，任一变化都重新订阅。
- 用 `useRef` 容器：把所有 state 放一个 ref 对象，只订阅一次。
- 用 `useReducer`：合并强相关 state，但仍需监听整个对象。
- 用 `useMemoizedFn`：无需监听任何依赖，只订阅一次。

### 5. 闭包陷阱的"传染性"
- 如果事件回调捕获了旧 state，它调用的所有函数都会继承旧值。
- 防御策略：让最外层事件回调通过 ref 读取最新值，再作为参数传给内部函数。

### 6. addEventListener vs onScroll

| 特性 | addEventListener | onScroll (JSX) |
|------|------------------|----------------|
| React 自动更新 | ❌ 不会，需手动管理 | ✅ 自动更新 |
| 闭包陷阱 | ✅ 容易遇到 | ❌ 配合 useCallback 可避免 |
| 适用场景 | 全局事件（window、document） | DOM 元素事件 |
| 性能 | 需手动节流 | 需手动节流 |

- **onScroll + useCallback 能工作的原因**：
  React 每次渲染后自动将最新函数绑定到 DOM 事件，
  相当于 React 帮你做了"重新订阅"。
- **addEventListener 是手动操作**，脱离 React 掌控，
  需要自己处理闭包陷阱和清理。

### 7. 连续触发 N 次请求的原因
- 在 `addEventListener` 的 `useEffect` 中加了依赖并重新绑定，
  但没有在 return 中正确移除旧监听。
- 每次依赖变化都会**新增一个监听器**，旧监听器没有被移除，
  导致多个监听器同时存在。
- 滚动到底部时，所有监听器都被触发，于是连续发出 N 次请求。

### 8. 为什么 removeEventListener 能解决
- `useEffect` 的 return 在组件卸载或依赖变化前执行，正确移除旧监听器。
- 保证同一时间只有一个监听器存在，避免重复触发。

## 三、最佳实践建议

1. **DOM 元素事件** → 用 `onXxx` + `useCallback`
2. **全局事件** → 用 `addEventListener` + `useRef` / `useMemoizedFn`
3. **滚动事件** → 记得加节流（throttle）
4. **useEffect 中绑定事件** → 务必在 return 中清理
5. **多个 state 场景** → 优先用 `useRef` 容器或 `useMemoizedFn`
6. **需要基于旧值计算** → 用 `setState(prev => ...)` 函数式更新

---

## 四、一句话总结

> React 闭包陷阱的本质是：每次渲染创建新的 state 变量和新的函数，
> 而手动订阅的事件绑定的是旧函数，旧函数引用了旧变量。
> 解决核心是让事件回调在**触发时**读取最新值，
> 而不是在**订阅时**锁定旧值。
> onScroll 能自动工作是因为 React 帮你做了重新绑定；
> addEventListener 需要你自己处理清理和闭包问题。
